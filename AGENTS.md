# TOPICS contributor instructions

These instructions apply throughout this project.

At the start of every session, read `_notes/NEXT.md` first, then `_notes/README.md` and
`_notes/RULES.md`. Before proposing work, read `_notes/OBJECTIVES.md`. Before revisiting a
choice, read `_notes/DECISIONS.md`. Read the Lessons in `_notes/LOG.md` before diagnosing
causes, and `_notes/CHANGES.md` to understand recorded changes.

Follow `_notes/RULES.md` throughout the work. Record behaviour changes in `_notes/CHANGES.md`
in the same session, individual changes and lessons in `_notes/LOG.md`, and decision reversals
explicitly in `_notes/DECISIONS.md`. Keep `_notes/NEXT.md` current and remove completed tasks
from it; keep historical records in the log. Correct outdated notes before acting on them.

Use English for project files and absolute dates in notes. Announce new directories with their
purpose and whether they may be deleted. Keep temporary work outside the project tree.

Keep commit messages concise and write changelog novelty items in English, one or two lines
per item. Commit completed, verified changes and push them to the configured TOPICS origin,
as requested by the user. Never include local environments, raw run folders or credentials.

TOPICS is independent of PoliScreen. PoliScreen's notes are historical context: its release,
Docker, repository, naming and packaging tasks are not TOPICS tasks. Do not modify PoliScreen
as a side effect of TOPICS work. Never start Docker Desktop automatically; the user starts it.
Do not copy source code from another project without reviewing its licence and dependencies.

Use installed skills only when relevant. Simplicity must preserve requested functionality and
scientific validity. These files do not override higher-priority instructions or the user's
explicit requests.
